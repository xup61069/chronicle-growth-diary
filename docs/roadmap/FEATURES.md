# 功能 Roadmap

Chronicle 採取「先建立可驗證的私有資料邊界，再擴大協作與即時性」的策略。本文件區分**已完成 MVP**、**後續擴充**與**尚未承諾的架構方向**；它不構成發佈時程或功能承諾。每項後續工作開始前，仍須完成資料模型、擁有權、分享範圍、刪除路徑、成本與部署評估。

## 已完成 MVP 的設計準則

年度回顧、語音日記、儀表板、書冊、匯出、家庭反應與照片匯入均以 private-first 為預設。公開或連結分享不是私有資料的鏡像，而是經過欄位層級隔離的讀取模型；後續任何事件欄位、音訊、位置、反應、留言或 AI 輸出擴充，都必須先維持這個邊界。

文件匯出採瀏覽器端、使用者觸發的工作方式。一般 PDF／長圖片備份以 on-demand chunk 降低初始工作台成本；A5 書冊則由使用者在已開啟的私人預覽視窗中明確選擇列印或另存。這兩者都不會在背景自動處理或保存使用者內容。

## 後續工作準入條件

新增功能必須至少定義擁有者、受邀成員、公開讀者與未登入讀者的資料可見性，並為新增與刪除建立可測試的授權路徑。涉及 AI、語音、媒體或外部同步時，還需要逐次同意、資料去向、撤回與刪除行為；涉及即時能力時，則需另行評估持續連線與部署成本。

正式 Manus OAuth 工作階段的端對端 `diary.get` 驗證目前受外部登入入口 CloudFront 403 阻礙。這個外部限制不改變 local-auth 與單元測試中的私有資料邊界，但恢復後仍須補做正式整合驗證。
